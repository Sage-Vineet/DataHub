# 1. Purpose & Business Context
Brokers and QoE reviewers regularly need to hand off findings as a polished PowerPoint deck — to a buyer, an investment committee, or a lender — rather than as raw workpapers. Today that means manually re-keying numbers and charts from the QoE workbook into a separate PowerPoint file, which is slow, error-prone, and disconnects the deck from the underlying data the moment it's built. This feature lets a user generate a native, editable PowerPoint file directly from the completed QoE module content (SDE/EBITDA bridge, working capital, customer concentration, AR/AP aging, risk & opportunities, etc.), styled to the firm's own template, so the output looks like something a design team produced rather than a system export.
This feature is architected as a shared deck-rendering engine: the same slide-generation and template logic is reused by CM - 0001 (CIM/SIM Builder), with each feature supplying its own module-specific data source and slide-content menu. QE - 0014 is scoped here as the QoE-facing instance of that engine — the content menu, data bindings, and user stories below are QoE-specific, while the underlying template/layout engine, .potx handling, and native PPTX generation approach are intended to be built once and consumed by both features.
# 2. User Stories
- As a QoE reviewer, I want to generate a PowerPoint deck directly from my completed QoE tabs, so that I don't have to manually rebuild slides from scratch for every engagement.
- As a QoE reviewer, I want to choose which QoE sections are included in the deck, so that I can tailor the output to the audience (e.g., lender vs. buyer vs. internal review).
- As a firm admin, I want to upload our own PowerPoint template once, so that every deck generated by anyone on my team automatically matches our firm's branding and layout.
- As a QoE reviewer, I want the exported PowerPoint to be a fully native, editable file, so that I can make last-mile adjustments in PowerPoint itself before sending it out.
- As a QoE reviewer, I want charts and tables in the deck to reflect the same numbers as the underlying QoE module at the time of export, so that I'm not presenting stale or inconsistent figures.
# 3. Functional Requirements
- The system shall allow a user to initiate PowerPoint generation from within the QoE module for a specific deal.
- The system shall present a checkbox list of available QoE sections/tabs (Executive Summary, SDE/EBITDA Tab, Working Capital, Risk & Opportunities, CIM Comparison, Customer Concentration, Vendor Concentration, AR Aging, AP Aging) for the user to select for inclusion in the deck.
- The system shall generate one or more slides per selected section, using a predefined slide layout mapped to that section's data shape (e.g., a bridge/waterfall layout for SDE/EBITDA, a table layout for aging analyses, a chart layout for concentration data).
- The system shall render charts and tables as native, editable PowerPoint objects (native chart objects and tables), not as flattened images, wherever the underlying chart/table type supports native PPTX rendering.
- The system shall allow images (e.g., logos, exhibits) to be embedded as native images where a native chart/table equivalent is not applicable.
- The system shall allow a firm admin to upload a PowerPoint template file (.potx) at the firm level, and shall apply that template's slide master, color palette, and fonts to all decks generated by users at that firm.
- The system shall fall back to a default Centuriuum-branded template if no firm-level template has been uploaded.
- The system shall pull slide content directly from the live QoE module data at the time of generation, so that figures in the deck match the current state of the underlying workpapers.
- The system shall generate a new, timestamped version of the deck file each time the user regenerates it, and shall not overwrite a prior export.
- The system shall allow the user to download the generated .pptx file.
- The system shall log each deck generation event (user, deal, timestamp, sections included, template used) to the audit trail.
- The system shall display a generation-in-progress indicator and notify the user when the deck is ready, given that deck assembly may take longer than a typical page load.

# 5. Access & Security
- Roles with access: Broker, Accountant/QoE reviewer (any role with edit access to the QoE module for that deal).
- Roles explicitly excluded: Bank, Buyer, Company user — none of these roles have a native QoE workpaper view today, so none should be able to trigger deck generation. Company/Buyer/Bank may later receive the finished .pptx as a distributed deliverable, but that is a distribution/sharing action, not generation access, and is out of scope here.
- Firm-level template upload is restricted to firm admin roles.
Deal isolation confirmed: this feature is scoped to a single company/deal only. No cross-deal or cross-company visibility of data, documents, or search results. A generated deck may only pull QoE data from the deal it was generated within.
# 6. UI / UX Notes
- Platform: Web only. Deck generation and template configuration are analysis-heavy, desktop-caliber workflows and are excluded from the Mobile (light) companion experience per platform convention.
- Wireframe reference: N/A
Entry point is a "Generate PowerPoint" action within the QoE module, opening a checklist modal of available sections (mirroring the pattern established in QE - 0013 Workbook Export). On confirmation, the system shows a progress indicator and, on completion, offers a direct download plus a link to prior versions of the deck for that deal.

# 8. Out of Scope / Deferred
- Distributing or sharing the generated deck with Buyer, Bank, or Company roles — that is a data-room/distribution action belonging to a future distribution feature (see BR - 0008 pattern for teaser distribution as a reference model), not this spec.
- In-app slide rearranging, manual layout editing, or adding freeform slides beyond the QoE section checklist — this spec covers auto-generation only, not an in-browser deck editor. A manual editor may be considered as a later enhancement once the auto-generation engine is proven.
- CM - 0001 CIM/SIM-specific slide layouts and content menu — those belong in the CM - 0001 spec, which will consume the shared engine defined/implied here.
- Speaker notes generation, animation/transition styling, and video/multimedia embeds.
- QE - 0002 Full Tax Return Mapping content is not part of the default slide menu given its own spec notes it is not solvable on all engagements.
# 9. Open Questions
- Should the shared PPTX rendering/template engine be formally broken out into its own feature ID (e.g., under a new Platform/Shared module) so CM - 0001 and QE - 0014 both reference it as a Dependency, rather than each spec re-describing the same engine? Recommend resolving before CM - 0001 is specced.
- Where does firm-level .potx template storage and management live in the near term, given the Admin/Internal Ops Console has no feature ID yet? Needs a home (even an interim one) before this spec can move to Ready for Dev.
- Should a firm be able to maintain more than one template (e.g., one for buyer-facing decks, one for lender-facing decks), or is one template per firm sufficient at launch?
- What is the expected behavior if a QoE section is selected for inclusion but has incomplete data (e.g., Working Capital tab not yet finished) — block generation, generate with a placeholder slide, or silently omit the section?
- Does per-slide native chart type have a hard technical ceiling (e.g., waterfall/bridge charts may not have a clean native PPTX chart equivalent and may require a workaround) — needs a technical spike before implementation estimate is final.
# 10. Acceptance Criteria
- User can select any combination of available QoE sections from a checklist and generate a .pptx file containing one or more slides per selected section.
- Exported .pptx opens natively in PowerPoint with editable text, tables, and native chart objects (not flattened images) for all supported section types.
- If a firm-level .potx template has been uploaded, generated decks use that template's slide master, palette, and fonts; if none has been uploaded, decks use the default Centuriuum template.
- Figures in the generated deck match the current values in the source QoE tabs at the time of generation.
- Regenerating a deck for the same deal creates a new version and does not overwrite or delete the prior export.
- Every generation event appears in the deal's audit trail with user, timestamp, sections included, and template used.
- Only Broker and Accountant/QoE reviewer roles with QoE module access can trigger generation; Bank, Buyer, and Company roles cannot.
