# 1. Purpose & Business Context
The Q&A module is the system of record for formal, trackable questions and answers exchanged on a deal — most commonly a broker or QoE provider asking the company something needed to complete the CIM, populate the quality of earnings narrative, or resolve a reconciling item, with the company's response (and any supporting document) captured against that question permanently. It replaces the ad hoc email/call/spreadsheet exchange that currently produces no durable, attributable record of who asked what, who answered, and what evidence backs the answer. Every downstream automation that depends on the company's own commentary — QoE working capital notes (QE - 0006), risk and opportunity items (QE - 0007), the reconciling-item generator (QE - 0015), and CIM population (CM - 0004) — depends on this module existing as the single place formal Q&A lands.
# 2. User Stories
One story per user type that touches this feature.
- As a broker, I want to ask the company a question needed to complete the CIM and see the answer land in one trackable place, so that I don't lose it in email and can reference it later.
- As a QoE provider, I want to ask the company follow-up questions about specific financial line items and attach the company's supporting documents to that question, so that the reconciling narrative is traceable to its source.
- As a company user, I want to see the questions asked of me, respond with text and/or upload a document, and pick where that document should live in the data room, so that my answer and evidence are properly filed and not scattered.
- As a broker or company owner, I want to hide specific sensitive questions/answers from certain users or groups even though they'd otherwise have standard access to the deal, so that I control exposure of sensitive commentary on a case-by-case basis.
# 3. Functional Requirements
Numbered, testable statements the dev team can build against directly.
- The system shall allow any user with access to a deal (broker, QoE provider, company, buyer, bank, accountant, per their standard role permissions) to create a new Q&A item consisting of a question and a target requestee.
- The system shall record, per Q&A item, the requestor, the requestee, the date asked, the date answered, and the answer text.
- The system shall allow the requestee (or any user permitted to respond) to reply to a Q&A item with text, an uploaded document, or both.
- The system shall support threaded follow-up replies on a single Q&A item, preserving the full back-and-forth in chronological order under that item rather than spawning disconnected new items.
- The system shall present the uploader with a folder picker at time of upload and require the uploader to select a destination folder in the Data Room before the document upload completes.
- The system shall store a reference linking the uploaded document to both its Data Room location and the originating Q&A item, so the document is discoverable from either place.
- The system shall track a status per Q&A item (e.g., Open, Answered, Follow-Up, Closed) and allow the requestor or an authorized role to change that status.
- The system shall, by default, apply the deal's standard role-based permissions to determine who can view a given Q&A item.
- The system shall allow the item's requestor (or the broker/company owner) to override default visibility by hiding a specific Q&A item from one or more named users or role groups, independent of those users' standard deal access.
- The system shall tag each Q&A item with its source of origin (manually created, generated by QE - 0015, or generated by CM - 0004 Guided Q&A) for downstream reporting.
- The system shall make Q&A items and their answers available for reference/linking by other modules (QoE, Reports) per QA - 0002, without requiring this module to know the details of how each consuming module displays them.

# 5. Access & Security
- Roles with access: Broker, QoE Provider, Company, Accountant, Buyer, Bank — per each role's standard deal permissions (default visibility).
- Roles explicitly excluded: none by default at the module level; exclusion is handled via the per-item visibility override below, not a role-level lockout.
- Visibility override: the requestor, broker, or company owner may hide a specific Q&A item from named individual users or role groups, overriding what those users would otherwise see under standard deal permissions. This override must be visible/auditable to admins (see Dependencies — SY - 0003) so a hidden item is never invisible to everyone.
- Deal isolation confirmed: this feature is scoped to a single company/deal only. No cross-deal or cross-company visibility of Q&A data, documents, or search results.
# 6. UI / UX Notes
- Platform: Web + Mobile (light) — viewing questions, submitting text answers, and reading threaded follow-ups are available on mobile. Document upload/filing into the Data Room is web only, consistent with the platform's general mobile-light scope.
- Wireframe reference: N/A
A Q&A item should read like a lightweight ticket: question, requestor/requestee, dates, status, answer, and a growing thread of follow-up replies beneath it. When a document is attached, the UI must make the chosen Data Room destination folder visible on the item itself (not just buried in the data room), so anyone reviewing the Q&A thread can see where the evidence was filed without leaving the module.

# 8. Out of Scope / Deferred
- The logic that auto-generates reconciling/business questions (thresholds, P&L-adjacent question placement) — that belongs to QE - 0015.
- The logic that generates standard/custom CIM-population questions with one click — that belongs to CM - 0004.
- General document versioning behavior when a file is re-uploaded — belongs to the platform-wide Document Versioning capability (cross-cutting gap), not reinvented here.
- The notification/alerting mechanism itself (email/in-app alert on a new question or new answer) — belongs to the Notifications Hub (cross-cutting gap); this spec only assumes Q&A events are emitted for that hub to consume.
- Detailed UI for how QoE (QE - 0006, QE - 0007) or Reports surface linked Q&A content — belongs to QA - 0002.
# 9. Open Questions
- Notifications Hub does not yet exist as a specced feature — confirm whether Q&A ships with a minimal built-in email alert as a stopgap, or waits on the hub.
- Should a Closed Q&A item still accept new follow-up replies (auto-reopening it), or must it be explicitly reopened first?
- When a visibility override hides an item from a user/group, should that user see a placeholder ("a question is hidden from you") or no trace of the item at all?
- Should the source tag (manual / QE - 0015 / CM - 0004) be user-facing, or internal/reporting-only?
- Confirm which DB module table block Q&A items should be filed under for schema purposes (none of DB - 0001–0010 currently list a dedicated Q&A block) — flagging for Database module reconciliation.
# 10. Acceptance Criteria
- A user with deal access can create a Q&A item specifying a requestee, and the item records requestor, requestee, and date asked automatically.
- A requestee can answer with text and/or a document upload; the document upload requires selecting a Data Room destination folder before completing, and the resulting file is visible both in the Data Room and from the Q&A item.
- Date answered is recorded automatically when the first answer is submitted.
- A follow-up reply appends to the same Q&A item's thread in chronological order rather than creating a new disconnected item.
- Default visibility on a new Q&A item matches the viewer's standard deal role permissions with no additional configuration.
- The requestor, broker, or company owner can hide a specific Q&A item from a named user or group, and that user/group can no longer see the item while retaining their standard access to everything else.
- No user can view Q&A items belonging to a deal/company they do not have access to.
